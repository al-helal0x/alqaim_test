# apps/web

لوحة الإدارة + PWA — Next.js. **المسؤول:** العضو 7 — Web Frontend Lead.

Thin Client بالكامل (القسم 6.2): لا منطق أعمال هنا إطلاقاً — كل شيء عبر
core-api عبر HTTP فقط. الأنواع (`api-client`) تُولَّد تلقائياً من OpenAPI
المُصدَّرة من core-api (`packages/api-types`)، لا حاجة لانتظار تنفيذ Backend
الفعلي، فقط توقيع الـ Endpoint المتفق عليه من "يوم العقود".

## البنية
```
src/
├── app/            # صفحات Next.js (App Router)
├── components/      # مكونات خاصة بصفحات محددة
├── features/{module}/  # مكوّنات/منطق واجهة لكل module (مطابق لأسماء core-api/modules)
├── common/          # مكونات UI عامة مستقلة عن أي منطق أعمال
├── hooks/            # React hooks عامة (useXxx)
└── api-client/       # عميل HTTP + الأنواع المولَّدة من OpenAPI
```

## الحالة (محدَّثة)
- ✅ يبني وينجح فعلياً: `npm install && npm run build && npm run lint && npx vitest run` — 27 صفحة، صفر تحذيرات، 5/5 اختبار وحدة. Backend: 53 اختباراً ناجحاً (4 متخطّاة لغياب Redis في بيئة الاختبار).
- ✅ الدورة التجارية الكاملة أصبحت متاحة من الواجهة: الكتالوج (منتجات/فئات/وحدات قياس) ← الشركاء (عملاء/موردون) ← المخزون (أرصدة/حركات/تحويلات/تسويات) ← المبيعات (عروض أسعار→أوامر بيع→فواتير) ← المشتريات (أوامر شراء→استلام→فواتير) ← المدفوعات (حسابات بنكية/دفعات/سندات قبض) ← المحاسبة (شجرة حسابات/قيود/تقارير) ← الضرائب.
- ✅ `packages/api-types` محدَّثة لتشمل 68 مساراً (أُضيف GET /warehouses، GET /purchase-invoices، GET /payments، GET /receipts — كانت مفقودة، أضفتها كإصلاحات صغيرة لسدّ فجوات backend حقيقية اكتُشفت أثناء بناء الواجهة).
- ❌ لم تُبنَ بعد: شاشة POS (تحتاج UX متخصص لسلة مبيعات/جلسة كاشير — أُجِّلت عمداً)، شاشة مراجعة AI (`/ai/*` جاهزة في الـ backend لكن لا واجهة لها بعد)، `packages/ui-kit` كحزمة منفصلة.
- ❌ لا Playwright بعد.
