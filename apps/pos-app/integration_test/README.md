# اختبار Integration — تدفّق POS الكامل ضد سيرفر core-api حقيقي

راجع التعليق الكامل أعلى `pos_flow_test.dart` أولاً — هذا ملخّص سريع فقط.

## لماذا هذا الملف موجود

كانت الفجوة #5 في `STATUS.md` ("لم تُختبَر الشاشات فعلياً ضد سيرفر core-api
حقيقي قيد التشغيل") — كل التحقق السابق كان منطقياً فقط (اختبارات الوحدة +
قراءة كود السيرفر يدوياً). هذا الملف اختبار **integration حقيقي فعلي**:
لا mocks، نداءات شبكة فعلية لسيرفر يعمل بالفعل.

**لم يُشغَّل هذا الملف فعلياً بعد** — بيئة التطوير التي كُتب فيها لا تملك لا
Flutter SDK ولا سيرفر core-api ولا اتصال شبكة فعلي. راجَعته يدوياً بعناية
مقابل كود كل شاشة (نصوص الأزرار/الحقول بالضبط، شروط تفعيل الأزرار، تسلسل
التنقّل) — لكن التشغيل الفعلي الأول قد يحتاج تعديلات طفيفة.

## المتطلبات قبل التشغيل

1. سيرفر core-api يعمل فعلياً ومتاح على عنوان تقدر تصله من جهاز/محاكي
   الاختبار (مو بالضرورة نفس المضيف — `10.0.2.2` هو المضيف من محاكي
   أندرويد افتراضياً، راجع `env_config.dart`).
2. بيانات مُهيَّأة (seed) في قاعدة بيانات ذلك السيرفر:
   - مستخدم بريد/كلمة مرور صالحين، **عضو في شركة واحدة بالضبط**.
   - مستودع نشط واحد على الأقل لفرع ذلك المستخدم.
   - منتج نشط واحد على الأقل (وعميل واحد على الأقل) — حدّد كلمة بحث تُطابقهما
     عبر `TEST_PRODUCT_QUERY`/`TEST_PARTNER_QUERY`، أو اتركهما فارغين
     لاستخدام أول نتيجة بلا فلترة.
3. جهاز أو محاكي متصل: تأكد بـ `flutter devices`.

## التشغيل

```bash
flutter test integration_test/pos_flow_test.dart \
  --dart-define=API_BASE_URL=http://localhost:8000 \
  --dart-define=TEST_EMAIL=cashier@example.com \
  --dart-define=TEST_PASSWORD=secret123 \
  --dart-define=TEST_PRODUCT_QUERY=coffee \
  --dart-define=TEST_PARTNER_QUERY=ahmad \
  -d <device-id>
```

بلا `TEST_EMAIL`/`TEST_PASSWORD` (مثال: أثناء تشغيل `flutter test` العادي
بلا `--dart-define` إضافية) يُتخطَّى الاختبار تلقائياً (`markTestSkipped`)
بدل أن يفشل بلا سبب واضح — لا يكسر أي CI موجود لا يزوّد هذه القيم.

## ماذا لو فشل عندك؟

أرسل لي رسالة الفشل كاملة (نفس ما فعلناه مع بقية هذه الجولة) — على الأغلب
أحد هذين:
1. **بيانات seed ناقصة** (لا مستودع/منتج/عميل مطابق) — رسائل `expect(...,
   reason: ...)` بالملف تشرح تحديداً أيها ناقص.
2. **نص أو تسلسل تغيّر بكود شاشة فعلية** منذ كتابة هذا الاختبار — أصلحه
   فوراً في الملف نفسه.
